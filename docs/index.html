$ howto

— ask your terminal in plain words

Type what you want to do. Get a runnable command back — pre-typed at your own prompt, explained, and never executed for you.

install options source ↗ 
$ howto kill whatever is using port 3000
lsof -ti:3000 | xargs kill -9
  Find the process listening on port 3000 and force-kill it.
  ⚠ SIGKILL gives the process no chance to clean up.
  [2] kill $(lsof -ti:3000) — let it shut down cleanly
$ lsof -ti:3000 | xargs kill -9  ← Enter runs it. Ctrl-C discards.

Description

howto is a pure “question in, command out” program. With the shell wrapper installed, the answer doesn’t just print — it lands pre-typed at your prompt, so Enter runs it, your own line editor edits it, and Ctrl-C throws it away. The binary itself never executes anything and never blocks on input.

Every question is answered for this machine. The prompt sent to the model includes your OS, shell, installed binaries, and project markers — so “kill port 3000” answers with lsof on macOS and fuser where that’s what exists.

It behaves in pipes and scripts, too: stdout carries only the command, everything else goes to stderr. -p prints the bare command, -j structured JSON, and exit codes are an API — 0 ok, 1 error, 2 no sensible command. Agents can drive it without ever hanging on a prompt.

Install

  1. Install the binary. Prebuilt for macOS and Linux — or cargo install --path . from a checkout.

    curl -LsSf https://github.com/C0ldSmi1e/howto/releases/latest/download/howto-installer.sh | sh

  2. Set your API key — get one at platform.claude.com.

    export ANTHROPIC_API_KEY=sk-ant-...

  3. Add the shell wrapper. This is the part that puts commands at your prompt; without it, howto simply prints them.

    # ~/.zshrc   (bash: --init bash)
eval "$(howto --init zsh)"

Options

No quotes, no subcommands — everything after howto is your question. A few flags cover the rest:

$ howto compress this folder into a tar.gz
$ howto 2          # take option [2] from the last answer
$ howto --last     # show the last answer again — no API call
-p, --print
bare command on stdout, nothing else
-j, --json
structured JSON result, for scripts and agents
--explain
part-by-part breakdown of the command
--last
re-show the last answer, every command numbered
--init <shell>
print the shell wrapper (zsh, bash)
--config
config path and resolved settings
-v, --verbose
detected context, model, and latency on stderr

Safety

Designed so the dangerous path is always the deliberate one:

  • Nothing runs until you press Enter at your own prompt. There is no -y, on purpose.
  • Risky commands carry a ⚠ reason. A local blocklist catches rm -rf /-class commands, dd to raw devices, fork bombs, and curl | sh — regardless of what the model says.
  • High-danger commands are never pre-typed. They appear numbered, and typing howto 1 is the deliberate act that loads one.
